项目名称：AI-Lab-Commander (PyQt6 版)
目标： 在 Windows 环境下，通过 PyQt6 界面实时调度、监控并记录 6 个 AI 角色的协作过程。

1. 软件界面布局 (UI Blueprint)
界面采用“仪表盘”风格，分为四个主要功能区：
A. 左侧：CKO 深度沟通区 (The Bridge)
角色： 用户 + CKO (Gemini)。
功能： 需求打磨。在这里你可以自由输入草稿、上传文献。CKO 会基于你的历史数据进行追问，最终生成一份“锁定版”任务书。
组件： QTextEdit (对话流) + QPushButton (发送任务至团队)。
B. 中间：多路会议直播间 (The War Room)
角色： PM, Arch, Designer。
功能： 实时展示 AI 们“吵架”的过程。
组件： 采用类似社交软件的聊天气泡流，每个角色的头像旁标注其身份。
交互： 实时显示“PM 正在输入...”、“Arch 驳回了方案”等状态。
C. 右侧：执行与测试实验室 (Execution Lab)
角色： Coder (GLM), Tester (Claude)。
功能： 实时查看 GLM 编写的代码，以及测试员的运行日志。
组件： QCodeEditor (高亮显示代码) + QLogConsole (终端风格的测试输出)。
D. 底部：议程时间轴 (The Timeline)
功能： 代替 Git。用横向的时间轴标注每个关键节点（构思->方案->执行->修正->完工）。
组件： QProgressBar 或自定义图标按钮，点击可跳转查看历史记录。

2. 核心逻辑架构 (Back-end Logic)
A. 状态驱动引擎 (State Machine)
不使用 Git，我们通过一个 StateController 类管理流程：
State_Grounding: 仅激活 CKO 接口。
State_Debate: 循环调用 PM/Arch/Des 接口，直至满足跳出条件（PM Approve）。
State_Production: 激活 Coder 写入文件系统。
State_Verification: 激活 Tester 运行脚本并反馈。
B. 数据持久化 (No-Git Data Layer)
存储格式： Project_Root/data/sessions/{timestamp}.json
结构：
JSON
{
  "session_id": "20260211_01",
  "user_intent": "...",
  "meeting_logs": [{"role": "PM", "content": "..."}],
  "final_code": "...",
  "test_reports": "..."
}
回溯： 界面启动时读取 JSON，利用 PyQt 的 Model/View 架构实时渲染。

3. 六大角色交互指令 (Agent Interaction Design)
阶段 0：CKO 预热 (必须先实现)
逻辑： 只有当你点击“确认立项”，任务才会流向后续 AI。
CKO 任务： 整合用户输入 + 历史项目偏好 + 科研禁忌 -> 输出 Mission_Protocol.json。
阶段 1：方案三角博弈
交互逻辑：
Arch (Claude): 提出逻辑框架。
Designer (DeepSeek): 将框架转化为 Windows 下的 Python 实现步骤。
PM (GPT-4o): 审查两者，如果意见不合，强制双方再进行一轮迭代。
阶段 2：执行与纠错闭环
交互逻辑：
Coder (GLM-5): 读取方案，输出代码文件。
Tester (Claude): 尝试静默运行代码。
反馈： 如果报错，将 Traceback 实时弹窗显示在 UI 右侧，并自动发回给 Coder。

4. 给 Antigravity 的开发任务清单 (Dev Tasks)
请 Antigravity 按照以下步骤编写 Python 代码：
第一步：GUI 骨架
使用 QMainWindow 创建主窗口。
使用 QThread 处理所有 API 调用，严禁在主线程发请求（防止界面卡死）。
实现 Signal/Slot 机制，当 Coder 产出代码时，实时更新 UI 的代码窗口。
第二步：API 集成与对话流管理
集成 zhipuai 和 openai SDK。
设计一个 ChatHistoryManager 类，自动将对话内容格式化为 JSON 并存入本地。
第三步：CKO 交互逻辑
编写第一个功能模块：“CKO 深度访谈记录仪”。确保 Gemini 能够访问本地的“背景知识库”。
第四步：实时进度看板
开发一个自定义控件，展示当前是哪个 AI 在占用“话筒”，并实时更新任务完成百分比。

5. 验收标准
可见性： 我能在界面上看到 PM 是怎么“训斥”执行员的。
可控性： 我可以随时点击“停止”，介入 AI 之间的讨论。
完整性： 最后的成果（报告、代码、图表）能一键在 Windows 资源管理器中打开，且所有讨论记录都有 JSON 备份。
